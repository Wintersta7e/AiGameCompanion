# scripts

| Script | What it does | Run |
|---|---|---|
| `build.sh` | Release build (vite build + `cargo xwin build --locked`) into `release/` (cleared first): the exe cargo built, read from cargo's target directory, and `config.example.toml`. Sets `RUSTFLAGS` to remap the home directory in compiled-in paths and to turn on Control Flow Guard and CET compatibility (only Rust code compiled with the flag is instrumented), and repeats cargo-xwin's sysroot includes in `TARGET_CFLAGS_<target>` with the same remap for the C dependencies; clears the three wrapper/flag variables; exports the SDK and CRT pins from `scripts/ci-tools.env` and fails if the SDK directory for that pin is absent after the build. | `./scripts/build.sh` |
| `binary-audit.sh` | `binary-audit.sh audit [--public-runner] [--expected-version <v>] <dir\|zip\|file>...` counts path and key shapes (ASCII and UTF-16LE) and checks the exe's PE flags; `self-test` proves every shape is caught and no known false positive is; `shapes` prints the shape list. Identity strings come only from `CI_CHECK_IDENTITY`, never printed. | `./scripts/binary-audit.sh self-test` |
| `ci-check.sh` | The step table and its runner: each check is one `row`; a plain run executes every row this machine can run and ends by naming each row it did not run and why; `--job <tag>` runs one CI job's rows; `--list` prints the table. Missing or different tool versions fail their rows. Run it after `cargo fmt` too. | `./scripts/ci-check.sh` |
| `../crates/launcher/scripts/freshness.ts` | Lists each pin beside the newest upstream release and its date. Fails only when it could check nothing. | `./scripts/ci-check.sh --job freshness` |
| `../crates/launcher/scripts/pin-guard.ts` | Checks that versions are read only from the pin files and that those files keep their shape, and that Dependabot keeps its cooldown, groups and reasoned ignores; its self-test runs first in the same row. | `./scripts/ci-check.sh --job workflows` |
| `../crates/launcher/scripts/test-ids.ts` | Checks each test run's ids against its baseline in `scripts/test-baselines/`: a missing, added, renamed, re-statused or filtered-out test fails the run. On a pull request it lists the ids changed since the base commit. | `cargo test ... 2>&1 \| node crates/launcher/scripts/test-ids.ts libtest scripts/test-baselines/linux.list` (a row of `ci-check.sh`) |
| `test-baselines/` | One `<id> <status>` line per test, sorted: `linux.list` for the Linux run, `windows.list` for the Windows-target run. Written only by the update switch, which is local only and refused in CI. | `CI_CHECK_UPDATE_BASELINES=1 ./scripts/ci-check.sh` |
| `../crates/launcher/scripts/wiring-check.ts` | Checks the workflows against the step table: one plain `ci-check.sh --job <tag>` call per job, every table tag called by exactly one needed job (a tag with a non-blocking row by exactly one job the aggregate job does not need), the weekly-run condition on exactly the beta canary and freshness jobs, `RUSTUP_TOOLCHAIN` only in a job on the non-blocking list, an aggregate job that needs every other needed job and fails on any result but success, the triggers, concurrency, timeouts, colour settings, the required job names, `--locked` on every cargo call that reads the dependency graph (rows and `build.sh`), read-only token permissions with no persisted credentials, and text that must not come back. Parses the workflow files itself and fails on any shape it does not recognise. | `node crates/launcher/scripts/wiring-check.ts` |
